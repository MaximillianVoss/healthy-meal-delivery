# Архитектура и критерии приёмки

Сначала разрабатывается один веб-проект с отдельными слоями предметной модели, прикладных сценариев и доступа к данным. Преждевременное разделение на микросервисы не требуется.

Клиент просматривает доступные блюда, пищевую ценность и аллергены, собирает заказ и выбирает интервал. Оператор подтверждает наличие и назначает курьера. Курьер обновляет только назначенные доставки. Администратор управляет ролями. Изменение меню не меняет стоимость уже оформленных заказов.

Первый рабочий этап должен проверить: загрузку меню; корректную сумму с положительным количеством; сохранение заказа с адресом и интервалом; разграничение ролей; допустимые переходы статусов; сохранность после перезапуска; отсутствие секретов в журнале. Все проверки сначала используют отдельную тестовую БД и вымышленные записи.

На этапе проектирования нет обещания готового сервиса: каталог src зарезервирован под будущую реализацию. Данные реальных клиентов, пароли, номера банковских карт и подписанные учебные отчёты в Git не включаются.
