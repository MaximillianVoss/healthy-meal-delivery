# Правила основной ветви

Целевая ветвь: main. После публикации применяются следующие правила GitHub Branch Protection или эквивалентного Ruleset: изменения через Pull Request; один одобряющий отзыв; сброс прежнего одобрения после новой правки; успешная обязательная проверка repository-structure; ветка актуальна относительно main; обсуждения разрешены; принудительная запись и удаление main запрещены. Администратор сохраняет аварийный обход с письменным обоснованием.

Конкретные параметры API подготовлены в branch-protection.example.json. Их наличие в Git не означает, что сервер уже применил защиту. До создания репозитория применить правила невозможно. После публикации нужно получить настройки обратно через API и приложить их к проверке. Если тариф или разрешения запрещают правила, это фиксируется как невыполненное условие, а не заменяется картинкой файла.

Рабочие ветви: feature/<описание> и fix/<описание>. Запрещено включать личные данные и секреты в названия ветвей, коммиты и Issue. Контекст CI должен совпадать с названием реального job repository-structure; после первой серверной проверки его следует сверить по GitHub Actions.
